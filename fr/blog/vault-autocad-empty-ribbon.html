Onglet Vault vide dans AutoCAD : l'onglet est là, mais aucun bouton

lundi 3 août 2026
VaultAutoCADCAO

Sur un poste équipé d'AutoCAD Mechanical 2025 et du client Vault 2025, le complément Vault semble se charger correctement : l'onglet Vault est présent dans le ruban, les groupes de fonctions aussi… mais ils sont vides. Aucun bouton. Impossible d'extraire ou d'archiver un fichier depuis AutoCAD.

Pas de message d'erreur, rien dans la ligne de commande. Le complément a l'air à moitié chargé.

Comment le ruban Vault est construit

Pour comprendre le symptôme, il faut regarder le PackageContents.xml du bundle :

<ComponentEntry AppName="Vault Plugin Partial Menu"
                ModuleName="./Contents/VaAc.cuix"
                LoadOnAutoCADStartup="True">
  <RibbonControls>
    <RibbonControl Name="Vaac"
        Path="pack://application:,,,/vaac_startupUIMgd;component/VaacControls.xaml"/>
  </RibbonControls>
  <AssemblyMappings>
    <AssemblyMapping Name="vaac_startupUIMgd"
        Path="./Contents/vaac_startupUIMgd.dll"/>
  </AssemblyMappings>
</ComponentEntry>

Le ruban Vault est construit en deux temps :

  • le fichier CUIx définit l'onglet et les groupes de fonctions. Un CUIx n'est pas lié à une version d'AutoCAD : il se charge toujours ;
  • les boutons sont des contrôles WPF chargés depuis l'assembly vaac_startupUIMgd.dll via l'URI pack pack://application:,,,/vaac_startupUIMgd;component/VaacControls.xaml.

Un onglet et des groupes présents mais vides signifient donc que le CUIx s'est chargé, alors que le chargement de vaac_startupUIMgd.dll a échoué — silencieusement.

La vraie cause

En listant les bundles installés sur la machine, un dossier attire l'attention : VaultAutoCAD2027.bundle, installé avec la beta du client Vault 2027. Son PackageContents.xml déclare :

<RuntimeRequirements OS="Win64" Platform="AutoCAD|ADT|Civil3D|..."
                     SeriesMin="R25.0" SeriesMax="R32.0" ... />

SeriesMin="R25.0" : ce bundle se déclare compatible avec AutoCAD 2025, alors que ses binaires (version 32.0.71.0) sont compilés pour AutoCAD 2027 (R26.0). À titre de comparaison, le bundle Vault 2026 est correctement borné avec SeriesMin="R25.1" SeriesMax="R25.1".

Et ce n'est pas tout : les bundles Vault 2025 et 2027 partagent le même ProductCode. Pour l'autoloader d'AutoCAD, il s'agit donc de la même application installée en deux versions, et c'est celle avec l'AppVersion le plus élevé qui gagne : 32.0.0.0 contre 30.0.0.0.

Résultat dans AutoCAD Mechanical 2025 :

  1. l'autoloader retient le bundle Vault 2027 ;
  2. son CUIx se charge sans problème → l'onglet et les groupes apparaissent ;
  3. son vaac_startupUIMgd.dll version 32, compilé contre les assemblys d'AutoCAD 2027, échoue à se charger → aucun bouton ;
  4. aucune erreur n'est remontée à l'utilisateur.

Le même défaut casse d'ailleurs le complément Vault dans AutoCAD 2026, dont la série R25.1 est aussi dans la plage fautive.

La solution

Il suffit de corriger SeriesMin dans le PackageContents.xml du bundle 2027 pour qu'il ne se charge que dans AutoCAD 2027. Dans une console PowerShell en administrateur :

$file = 'C:\Program Files\Autodesk\ApplicationPlugins\VaultAutoCAD2027.bundle\PackageContents.xml'
Copy-Item $file "$file.bak"
(Get-Content $file -Raw) -replace 'SeriesMin="R25\.0"', 'SeriesMin="R26.0"' |
    Set-Content $file -Encoding utf8BOM

Après redémarrage d'AutoCAD Mechanical 2025, l'autoloader ne retient plus que le bundle Vault 2025 : les boutons de l'onglet Vault sont de retour.

Dernier point de vigilance : une mise à jour du client Vault 2027 beta peut réécrire ce fichier avec la plage fautive. Si l'onglet Vault se vide à nouveau un jour, c'est le premier endroit à vérifier.
